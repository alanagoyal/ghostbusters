# Local-first agent runbook

Owner prompt: **“Get Ghostbusters working with my doorbell. It is a <brand/model> on the Wi-Fi network this computer is on.”**

The agent does the setup. The owner may need to enter the camera's local username/password privately, enable local streaming / watch-always access in its app, allow macOS Camera/Local Network access, or choose a device when several are found. No cloud account, credit card, Docker, router administration or known IP is required for supported discovery. Some cameras cannot supply a local stream: do not promise universal doorbell support.

## Supported release scope

Full local classification and DoorBird walkthroughs were verified on an **M4 Mac mini (16 GB)** and **M2 MacBook Air (24 GB)** with macOS and Python 3.11. MLX needs a usable Metal GPU/session. The `models` and `up` commands check GPU access before downloading or starting. If an agent sandbox blocks Metal, run the same command in an authorized host terminal. Apple Silicon with 16 GB is the installation floor, not a benchmark of every chip. Linux, Windows and Raspberry Pi full-local inference are **not supported by this release**. Existing cloud capture remains available on its previous platforms; do not install MLX there. A Pi can supply a compatible stream to a supported Mac; it is not claimed to run the model.

Camera adapters:

- DoorBird: documented `_http._tcp` Bonjour; fallback to existing ARP neighbors in Bird's IEEE allocations, then an unauthenticated vendor page. No subnet sweep. When credentials are supplied, one read-only Digest `info.cgi` check per confirmed candidate (at most 16), stopping at the first valid BHA response. Continuous Digest MJPEG `/bha-api/video.cgi`, respecting reconnect delays. The protocol may be interrupted by other camera activity.
- USB: macOS AVFoundation enumeration, then owner device selection; camera permission required. No physical USB camera has yet been verified on this host.
- ONVIF/compatible RTSP: WS-Discovery, device/media profiles and RTSP URI negotiation. Credentials remain scoped to the selected device; cross-host media/stream addresses are rejected. Network/vendor variation is substantial; hardware testing is still required for a particular model. RTSP-only devices that cannot advertise ONVIF need a vendor discovery adapter; do not ask owners to guess a URL.
- Ring/Nest and other vendor-cloud-only models: **unsupported without an adapter**. Enabling local streaming is an owner step only where the vendor actually offers it. Never change camera settings automatically.

Protocol sources: [DoorBird LAN API](https://www.doorbird.com/downloads/api_lan.pdf), [IEEE MA-M](https://standards-oui.ieee.org/oui28/mam.csv), [IEEE MA-L](https://standards-oui.ieee.org/oui/oui.csv), [ONVIF operations](https://www.onvif.org/onvif/ver20/util/operationIndex.html). Vendor prefix identifies candidates, not trust; authenticated identity remains required. On a hostile LAN, discovery is not cryptographic device attestation.

## Agent steps (resumable)

1. Inspect host/platform/RAM and existing `.env`/runtime *without printing secrets*. Preserve existing Baseten selection, optional Supabase, running services, cloud resources. Never provision cloud unless the owner explicitly chooses it. A fresh clone defaults local; an existing configured cloud clone keeps legacy commands. `ghostbusters local …` explicitly selects the isolated local installation without reading `.env`.
2. Install Python **3.11**, uv and Node 22+ using official distributions if absent. Keep tool installs local when possible. Run `uv sync --frozen --python 3.11 --extra local`. No global login. On unsupported hardware stop with a precise hardware requirement or offer the explicitly opted-in cloud runbook.
3. `uv run --no-sync ghostbusters local setup --brand doorbird` (or `usb`, `onvif`). JSON output and stable exit codes: **0 ready/success, 2 owner/agent action required, 3 failure**. A missing model/build is an agent task, not an owner question. Re-running preserves config, records, identity and credentials. Changing the selected device clears previous credentials.
4. Securely collect only required local credentials into a private dotenv file (`DOORBIRD_USERNAME`/`DOORBIRD_PASSWORD` or `CAMERA_USERNAME`/`CAMERA_PASSWORD`, mode 0600 in a 0700 directory). Never values in shell argv, logs or screenshots. Run `… local setup --brand doorbird --credentials-file /private/path/camera.env`. For other multiple candidates, use returned opaque ID with `--select ID`; show human-readable names, not require a known IP. Delete the handoff file after successful import if no longer needed.
5. `… local models`: public model + YOLO downloads only, no camera images leave the computer. Then `… local build`: npm install and production static build. No dev watcher. All `uv run` commands in this runbook use `--no-sync` after the frozen local-extra sync so optional runtime dependencies are retained.
6. `… local camera-check --seconds 15 --save-preview` while this installation is stopped. Continuous decoded frames must succeed; a still alone is not proof. Preview is `.ghostbusters/local/preview.jpg` mode 0600. Inspect privately on the host, never publish a raw preview. Configure normalized ROI with `… local setup --roi LEFT RIGHT TOP BOTTOM` (default full frame); preview dimensions and your local inspection guide the crop. Do not change the owner's camera settings or stop unrelated capture services.
7. `… local up`: starts the gallery/API, capture and durable classifier under this installation's supervisor. They remain running after the agent exits. It reports the usable loopback gallery location; `… local link` emits a **private access link** whose fragment is exchanged for an HttpOnly cookie. Do not put that token in public artifacts. API/events/images require authentication even on loopback. Remote sharing is explicit opt-in through an authenticated tunnel, and must retain gallery access protection. No BB dependency is shipped.
8. `… local status` reports health and pending work. Verify a real person enters the ROI; record the real detection and classification result. Never call synthetic-fixture success a real-person walkthrough. `… local stop` only stops this installation; `up/start/stop` are idempotent. No legacy launch-agent labels are used. For host reboot, rerun `up`; automatic login/boot launch is not installed. A supervisor restarts failed children; abrupt parent death releases child locks after the parent watchdog detects it.

Use `GHOSTBUSTERS_HOME=/absolute/private/directory` to isolate a second install/test. It gets its own ID, DB, credentials, locks and process registry. Select an unused port with `local setup --port 3327`; port collision fails without killing another service. Never copy cloud credentials into fresh verification installs.

## Storage, privacy and failure behavior

SQLite WAL migrations are idempotent (`user_version=1`); records/images persist through restarts. No cloud account or internet access is required after public models/dependencies download. Raw person crops stay local, private and unblurred to preserve costume detail; do not expose them publicly. Local inference runs offline. Cloud paths retain their existing privacy/blur behavior.

Keep a laptop awake with its lid open and connected to power during capture. The local supervisor does not prevent sleep or install startup-at-login; run `local up` after a reboot. LAN cameras still require a working local network.

Defaults: seven-day retention, 2 GB image budget, 500 MB free-disk reserve, 32 queued jobs, 30-second save cooldown per detection type (person vs. inflatable candidate), with continuous scanning. Set `--retention-days` / `--max-image-mb`; advanced values live in private `config.json` while stopped. Oldest detections/images are evicted first. Retention may cancel a processing record; worker completion becomes a harmless no-op. A new person arriving within the same person-save cooldown may be skipped; this is not per-visitor tracking. Same-frame groups are saved together. Queue-full records keep their photo with an honest state, and are not silently classified later. Classification runs separately from latest-frame capture, with three bounded attempts including crashed/expired leases; final failures keep their image. A stalled inference job is restarted after its 120-second lease. Model startup has a 180-second deadline; three consecutive startup timeouts stop retries until `local stop` then `local up`. No confidence score is calibrated; guesses can be wrong. Counts are retained detection records, including candidate/failure states, not unique people.

Maintenance is periodic; allow transient image-budget overshoot between sweeps. SQLite/index overhead and model downloads are additional to the image budget. Disk-full pauses new detections and reports storage health. Stale frame timestamps must be treated as capture failure even if the process exists. Lost streams refresh the selected identity via discovery rather than sending credentials to a previously occupied IP. If a device cannot be rediscovered, fix LAN/power/discovery; do not spray its password at other hosts.

## Verification

Offline: `uv run --no-sync python -m unittest discover -s backend/tests/unit -v`; `npm --prefix frontend run typecheck`; `ghostbusters local build`.

Licensed fixture sources and expected visual content: `backend/tests/fixtures/local/README.md`. Live model tests are separate from offline unit tests. See `docs/LOCAL_BENCHMARK.md` for measured model quality/limits.

Existing cloud installs: [Baseten](BASETEN_SETUP.md), [Supabase](SUPABASE_SETUP.md), and [CLI](CLI.md). Existing Baseten installs stay Baseten unless explicitly switched. Do not commit `.env`, `.ghostbusters`, models or camera footage.
